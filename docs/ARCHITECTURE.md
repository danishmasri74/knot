# Architecture

React owns navigation, title editing, library queries, status, and application actions. BlockSuite owns rich text, canvas rendering, drawing, selection, and undo/redo. The editor is mounted as a custom element and is not rerendered on pointer events.

- `src/app`: application shell and active-document lifecycle.
- `src/features/editor/blocksuite/adapter.ts`: the only BlockSuite integration boundary; schema registration, collection/subdocument initialization, BlobSource, mode switching, snapshots, and disposal.
- `src/services/workspace.ts`: typed Tauri command APIs for documents, attachments, and backups.
- `src/services/persistence.ts`: bounded, serialized asynchronous save coordination.
- `src-tauri/src/storage.rs`: migrations, workspace initialization, SQLite transactions, asset hashing and storage.
- `src-tauri/src/organization.rs`: folder/tag catalog, atomic assignments and filtered library queries.
- `src/app/Organization.tsx`: organization management, document assignment and library filter controls.
- `src-tauri/src/backup.rs`: consistent SQLite snapshots and validated archive restoration.
- `src-tauri/src/lib.rs`: narrow commands and default workspace selection.
- `src-tauri/src/workspaces.rs`: managed/external workspace discovery, persisted selection, safe switching and copy-based relocation.
- `src/app/WorkspacePicker.tsx`: workspace picker, native folder actions and location display.

The editor projects live workspace metadata into a session-scoped BlockSuite collection. Only the active document and its transitively referenced documents have their bodies loaded; cycles are visited once. Library reads are paginated in batches of 100, with indexed ordering and title substring filtering. The reference catalog reads all metadata pages, so collection metadata memory grows with library size. A future FTS migration can replace the substring scan. React retains no attachment payloads in state. BlobSource loads a requested asset only when needed.

Each object has a stable UUID independent of its display title or mode. SQLite `objects` owns the workspace catalog; `documents.document_state` holds the sole authoritative Yjs body for each object. On open, the adapter validates the legacy per-object collection envelope and applies its document update to the matching workspace subdocument. Existing bodies and IDs are preserved; no bulk rewrite or SQLite schema change is required. Per-object collection envelopes are retained and their title metadata is maintained for compatibility, but they are no longer the runtime reference catalog.

Shared placements are native `affine:embed-synced-doc` blocks containing a `pageId` and board-local layout. Native `affine:embed-linked-doc` cards and inline reference attributes use the same workspace IDs. There is no second note body or denormalized preview stored on a board. Preview rendering reads the referenced subdocument; opening its card navigates through the app's flush/history path. Shared previews are read-only; edit the source to update every placement. Removing or undoing a placement only changes its owning document. Soft-deleted targets are absent from the runtime catalog and render as unavailable, while their stored bodies and referring IDs remain intact.

One SaveCoordinator observes every loaded subdocument. A save transaction commits all dirty bodies and their titles together, including new documents created by BlockSuite's native linked-document operations. Failed transactions preserve all prior snapshots and retain the dirty set for retry. Unloaded metadata placeholders are never saved as empty documents. Workspace changes and editor disposal discard the session collection; switching reconstructs references from committed source content. The single-window workspace lock remains the concurrency boundary. Attachments continue to resolve through the workspace BlobSource and are retained globally for backups; no reference-aware garbage collection is introduced.

The Rust workspace mutex serializes storage operations, so a backup contains a coherent metadata/asset view. Tauri async commands keep database work off the WebView rendering thread, though long backup operations currently delay subsequent commands. A dedicated blocking worker is a future refinement.

Trash queries read soft-deleted catalog rows in stable deletion-date/ID order, with title search and 100-row pages. Explicit restore clears only `objects.deleted_at`; snapshots, edit timestamps, attachments, IDs and remaining organization assignments are preserved. Normal saves still cannot resurrect deleted objects. The shell flushes pending changes before restoring, then reconstructs the active editor collection so references to the restored ID resolve immediately. Restore does not add a navigation-history visit or change library filters. No schema migration or destructive cleanup is involved.

No arbitrary path-based file commands are exposed. Backup and external workspace paths come from Rust native dialogs; asset paths are derived from validated SHA-256 strings. Network embeds are intentionally restricted by the production CSP.

The workspace picker accepts validated managed directory IDs or opaque external IDs registered by the native folder dialog. Managed candidates must have a manifest and database; canonical-parent checks exclude redirects outside the managed folder. External paths are canonicalized, deduplicated, and stored in `external-workspaces.json`; arbitrary paths are never accepted as command arguments. Both paths require existing manifests and databases before opening, so missing or disconnected folders are never initialized as empty replacements. External entries remain visible when unavailable. A malformed external registry is preserved and reported in the picker while managed workspaces remain available for recovery.

Opening validates the database and acquires the destination lock while the current lock remains held. External registration and active selection each use synced temporary files and atomic renames; selection is replaced before changing the active workspace. A failed open, registry write or selection write retains the old workspace. A successfully registered entry can remain in the picker after a selection-write failure. Legacy managed selection files remain compatible. Restore-backup, external opening, relocation and picker transitions share the frontend flush/reset path for editor sessions, history, organization filters, Trash, backups and references.

Relocation is deliberately copy-and-switch, with the source retained as an independent recovery copy. A native dialog chooses the parent folder; Knot rejects destinations inside the active workspace, exports a consistent archive, restores and validates it into a unique child, removes the intermediate archive, then opens and remembers the destination. No existing destination is overwritten. The manifest, stable document IDs, snapshots, organization, Trash and indexed attachments are preserved. Caches, unindexed files and application-managed backups are not relocated. If final selection fails, the error identifies the validated copy location and the original remains active. This works across filesystem volumes without requiring a directory rename, but actual cross-drive/removable/network storage acceptance remains untested. User-defined workspace names and automatic removal of the source remain future work.

Workspace ownership is protected by a process-held OS file lock. A second process refuses to open the same workspace; the lock is released after process termination. The title edited inside BlockSuite is saved with its snapshot and mirrored to library metadata. The application temporarily disables editor interaction during switching, importing, and backup/restore dialogs.

Managed backups live in the application data `Backups` directory, outside any workspace, so they remain available when the selected workspace cannot open. `managed_backups.rs` exposes only validated archive IDs, checks canonical containment, and serializes operations with the workspace mutex. The panel lists all managed archives with filename, modification time and byte size. Creation flushes editor changes and reuses the consistent SQLite/asset exporter; filenames include the source workspace directory, time and UUID. External backups saved through the native dialog are not added to this catalog.

Verification extracts into a unique temporary directory inside `Backups`, runs the existing manifest/database/relationship/attachment restore checks, and removes the extracted copy without changing the active workspace. Restore uses the shared selection transition and retains the current workspace on failure; a successfully extracted workspace remains discoverable if selection persistence fails. Deletion requires UI confirmation and removes only the selected archive. There is no automatic retention or scheduling. Local managed copies do not protect against loss of the disk; the existing native export supports copies elsewhere. Verification requires temporary space for the expanded archive and operations remain serialized.


Document exports flush pending saves before generating a payload and opening a Rust native Save As dialog. The shell disables editing and switching for the entire operation. Markdown uses BlockSuite's `Job`/`MarkdownAdapter`, exports supported page blocks, and includes referenced attachment bytes under `assets/` with `index.md` in a ZIP when needed. Shared notes and inline/card references remain workspace-ID links; no recursive document-body export is attempted. Unsupported blocks and canvas-only content are not a lossless interchange format.

PNG/PDF render the current view with BlockSuite's export manager. Canvas export explicitly passes canvas elements as well as blocks; the upstream default wrapper otherwise omits shapes. Page capture uses the pinned 0.19.5 internal `_toCanvas` bridge, and canvas capture calls its `_checkReady` hook before rendering. BlockSuite's SVG text conversion is retained to avoid clipped glyphs in WebView2. These compatibility hooks are isolated in the adapter and covered by native tests. Output is composited on white. PDF embeds this image on one page; it does not provide selectable text or pagination. Only local `blob:` fetches were added to CSP to allow attachment-image rendering; external network access remains restricted. The existing `pdf-lib` transitive version is now a pinned direct dependency.

`src-tauri/src/exports.rs` validates formats, safe archive paths, duplicate names and a 100 MiB aggregate payload cap. Output is written to a unique sibling temporary file, synced, then published with `tempfile::persist_noclobber` (a no-replace move on Windows). Failed writes clean up the temporary file and preserve existing destinations. Paths are supplied only by the native dialog. Visual exports are bounded to 16 megapixels and 16,000 pixels per side. Exports are currently in-memory IPC and are not intended for multi-gigabyte documents.

The integrity panel runs a read-only SQLite integrity/foreign-key check and the attachment hash/size audit after flushing pending editor saves. It lists affected attachment keys, filenames and stored document associations, including Trash, without rewriting snapshots. Associations are import history, not proof of current in-document use. Unindexed regular files directly in assets or one subfolder deep are listed and retained; a known hash at the wrong path is also unindexed. The report is timestamped, cleared before a new attempt and on workspace transitions, and links to backup management for separate-workspace recovery. Audit failures use the existing error/retry path. Large audits remain serialized and are not paginated; full schema validation and automatic repairs remain future work.

`quarantine.rs` adds explicit recoverable cleanup outside the attachment index. Preview scans ordinary files directly in `assets` and one level below, hashes their bytes and excludes any filename or content hash present anywhere in `attachments`. Thus indexed bytes remain protected even when associated only with Trash, no document, or a shared source. SQLite integrity and foreign-key checks must pass before preview/move. Unsupported relative names, links and Windows reparse points are excluded; no recursive traversal is performed. The broader integrity inventory can list files that this more conservative cleanup preview excludes.

Commands accept workspace-scoped candidate IDs plus preview size/hash, or quarantine UUIDs; the frontend cannot supply destination paths. The workspace mutex serializes preview revalidation and moves against Knot writes. Each selected file is matched against a fresh scan and rehashed before copying. A unique `quarantine/<UUID>/entry.json` records its relative original path, size, hash and time. Metadata and an independent no-replace payload copy are synced and verified before removing the source. Partial batches report per-file outcomes; interrupted or malformed entries remain on disk with catalog warnings. No database rows, document bodies, IDs, organization or attachment relationships are changed.

Restore validates the metadata and payload, validates ordinary parent directories, refuses existing destinations, and refuses content that conflicts with a newly indexed original path. It publishes a synced copy without replacing files and retains the quarantine payload even after successful restoration. Refresh and workspace transitions clear selections, and mutations flush pending editor saves. Recovery copies can still be listed if cleanup preview fails. Quarantine uses disk space and is intentionally excluded from existing backups and copy-based relocation, which already exclude unindexed files; the UI states this limitation. Permanent disposal, empty-directory removal, recovery-copy portability, pagination and cancellation are not implemented. Scans and payload verification are synchronous under the workspace mutex. External applications modifying workspace files concurrently and physical power-loss/full-disk behavior are not guaranteed by this slice.


The integrity command also captures catalog metadata and saved snapshot pairs for all live and trashed documents under the workspace mutex. The frontend decodes them into disposable Yjs documents, never into the active editor or a BlockSuite collection. It checks collection metadata identity, unresolved Yjs dependencies and exactly one page root, then checks card and inline target IDs against the complete catalog. Self references and cycles are valid; missing, trashed and unreadable targets receive distinct findings with source IDs. Missing snapshots are reported as possibly never opened, not proof of content loss. Snapshots are discarded after analysis; only findings remain in React state. No repair, migration or reference rewrite occurs. This is structural diagnosis, not full block-schema, attachment-use or rendering validation. All snapshot bytes currently cross IPC in one report and decoding runs synchronously in the WebView; large-library memory, pagination and cancellation remain future work. Existing read failures abort the report rather than showing stale success.

The report groups referenced Trash targets that pass the basic snapshot checks into explicit recovery actions, counting distinct referring documents including trashed sources. Missing or structurally damaged target snapshots do not receive a direct action; their findings point to document issues and recovery backups. Before acting, the shell flushes pending edits and reruns the audit, rejecting stale actions whose targets are no longer eligible. It reuses the existing restore command, which changes only the original object's deletion flag. The shared restore flow refreshes library/Trash, reconstructs the active editor collection without a history visit and reruns any visible integrity report. A committed restore is announced before subsequent refresh work, so a refresh failure cannot hide that it succeeded. Failed database restores leave the current report available for retry. No automatic batch restoration, snapshot replacement or migration is introduced; basic checks do not guarantee complete schema/rendering validity or healthy transitive dependencies. Revalidation is serialized with app actions but does not guarantee against external filesystem/database writers.
