# Architecture

React owns navigation, title editing, library queries, status, and application actions. BlockSuite owns rich text, canvas rendering, drawing, selection, and undo/redo. The editor is mounted as a custom element and is not rerendered on pointer events.

- `src/app`: application shell and active-document lifecycle.
- `src/features/editor/blocksuite/adapter.ts`: the only BlockSuite integration boundary; schema registration, collection/subdocument initialization, BlobSource, mode switching, snapshots, and disposal.
- `src/services/workspace.ts`: typed Tauri command APIs for documents, attachments, and backups.
- `src/services/persistence.ts`: bounded, serialized asynchronous save coordination.
- `src-tauri/src/storage.rs`: migrations, workspace initialization, SQLite transactions, asset hashing and storage.
- `src-tauri/src/migrations.rs`: transactional schema initialization/upgrades and retained pre-upgrade recovery archives.
- `src-tauri/src/collections.rs`: collection catalog, atomic memberships/create-and-add and filtered notebook queries.
- `src/app/Collections.tsx`: contextual create/add popovers, inline Collections accordion and inline rename/delete.
- `src-tauri/src/backup.rs`: consistent SQLite snapshots and validated archive restoration.
- `src-tauri/src/lib.rs`: narrow commands and default workspace selection.
- `src-tauri/src/workspaces.rs`: managed/external workspace discovery, persisted selection, safe switching and copy-based relocation.
- `src/app/WorkspacePicker.tsx`: workspace picker, native folder actions and location display.

The editor projects live workspace metadata into a session-scoped BlockSuite collection. Only the active document and its transitively referenced documents have their bodies loaded; cycles are visited once. Library reads are paginated in batches of 100, with indexed ordering and title substring filtering. The reference catalog reads all metadata pages, so collection metadata memory grows with library size. A future FTS migration can replace the substring scan. React retains no attachment payloads in state. BlobSource loads a requested asset only when needed.

Each object has a stable UUID independent of its display title or mode. SQLite `objects` owns the workspace catalog; `documents.document_state` holds the sole authoritative Yjs body for each object. On open, the adapter validates the legacy per-object collection envelope and applies its document update to the matching workspace subdocument. Existing bodies and IDs are preserved; no bulk rewrite or SQLite schema change is required. Per-object collection envelopes are retained and their title metadata is maintained for compatibility, but they are no longer the runtime reference catalog.

Shared placements are native `affine:embed-synced-doc` blocks containing a `pageId` and board-local layout. Native `affine:embed-linked-doc` cards and inline reference attributes use the same workspace IDs. There is no second note body or denormalized preview stored on a board. Preview rendering reads the referenced subdocument; opening its card navigates through the app's flush/history path. Shared previews are read-only; edit the source to update every placement. Removing or undoing a placement only changes its owning document. Soft-deleted targets are absent from the runtime catalog and render as unavailable, while their stored bodies and referring IDs remain intact.

One SaveCoordinator observes every loaded subdocument. A save transaction commits all dirty bodies and their titles together, including new documents created by BlockSuite's native linked-document operations. Failed transactions preserve all prior snapshots and retain the dirty set for retry. Unloaded metadata placeholders are never saved as empty documents. Workspace changes and editor disposal discard the session collection; switching reconstructs references from committed source content. The single-window workspace lock remains the concurrency boundary. Attachments continue to resolve through the workspace BlobSource and are retained globally for backups; no reference-aware garbage collection is introduced.

The Rust workspace mutex serializes storage operations, so a backup contains a coherent metadata/asset view. Tauri async commands keep database work off the WebView rendering thread, though long backup operations currently delay subsequent commands. A dedicated blocking worker is a future refinement.

Trash queries read soft-deleted catalog rows in stable deletion-date/ID order, with title search and 100-row pages. Explicit restore clears only `objects.deleted_at`; snapshots, edit timestamps, attachments, IDs and remaining organization assignments are preserved. Normal saves still cannot resurrect deleted objects. The shell flushes pending changes before restoring, then reconstructs the active editor collection so references to the restored ID resolve immediately. Restore does not add a navigation-history visit or change library filters. No schema migration or destructive cleanup is involved.

No arbitrary path-based file commands are exposed. Backup and external workspace paths come from Rust native dialogs; asset paths are derived from validated SHA-256 strings. Network embeds are intentionally restricted by the production CSP.

The workspace picker accepts validated managed directory IDs or opaque external IDs registered by the native folder dialog. Managed candidates must have a manifest and database; canonical-parent checks exclude redirects outside the managed folder. External paths are canonicalized, deduplicated, and stored in `external-workspaces.json`; arbitrary paths are never accepted as command arguments. Both paths require existing manifests and databases before opening, so missing or disconnected folders are never initialized as empty replacements. External entries remain visible when unavailable. A malformed external registry is preserved and reported in the picker while managed workspaces remain available for recovery.

Opening validates the database and acquires the destination lock while the current lock remains held. External registration and active selection each use synced temporary files and atomic renames; selection is replaced before changing the active workspace. A failed open, registry write or selection write retains the old workspace. A successfully registered entry can remain in the picker after a selection-write failure. Legacy managed selection files remain compatible. Restore-backup, external opening, relocation and picker transitions share the frontend flush/reset path for editor sessions, history, organization filters, Trash, backups and references.

Relocation is deliberately copy-and-switch, with the source retained as an independent recovery copy. A native dialog chooses the parent folder; Knot rejects destinations inside the active workspace, exports a consistent archive, restores and validates it into a unique child, removes the intermediate archive, then opens and remembers the destination. No existing destination is overwritten. The manifest, stable document IDs, snapshots, organization, Trash and indexed attachments are preserved. Caches, unindexed files and application-managed backups are not relocated. If final selection fails, the error identifies the validated copy location and the original remains active. This works across filesystem volumes without requiring a directory rename, but actual cross-drive/removable/network storage acceptance remains untested. User-defined workspace names and automatic removal of the source remain future work.

Workspace ownership is protected by a process-held OS file lock. A second process refuses to open the same workspace; the lock is released after process termination. The title edited inside BlockSuite is saved with its snapshot and mirrored to library metadata. The application temporarily disables editor interaction during switching, importing, and backup/restore dialogs.

Managed backups live in the application data `Backups` directory, outside any workspace, so they remain available when the selected workspace cannot open. `managed_backups.rs` exposes only validated archive IDs, checks canonical containment, and serializes operations with the workspace mutex. The panel lists all managed archives with filename, modification time and byte size. Creation flushes editor changes and reuses the consistent SQLite/asset exporter; filenames include the source workspace directory, time and UUID. External backups saved through the native dialog are not added to this catalog.

Verification extracts into a unique temporary directory inside `Backups`, runs the existing manifest/database/relationship/attachment restore checks, and removes the extracted copy without changing the active workspace. Restore uses the shared selection transition and retains the current workspace on failure; a successfully extracted workspace remains discoverable if selection persistence fails. Deletion requires UI confirmation and removes only the selected archive. There is no automatic retention or scheduling. Local managed copies do not protect against loss of the disk; the existing native export supports copies elsewhere. Verification requires temporary space for the expanded archive and operations remain serialized.

Document exports flush pending saves before generating a payload and opening a Rust native Save As dialog. The shell disables editing and switching for the entire operation. Markdown uses BlockSuite's `Job`/`MarkdownAdapter`, exports supported page blocks, and includes referenced attachment bytes under `assets/` with `index.md` in a ZIP when needed. Shared notes and inline/card references remain workspace-ID links; no recursive document-body export is attempted. Unsupported blocks and canvas-only content are not a lossless interchange format.

PNG/PDF render the current view with BlockSuite's export manager. Canvas export explicitly passes canvas elements as well as blocks; the upstream default wrapper otherwise omits shapes. Page capture uses the pinned 0.19.5 internal `_toCanvas` bridge, and canvas capture calls its `_checkReady` hook before rendering. BlockSuite's SVG text conversion is retained to avoid clipped glyphs in WebView2. These compatibility hooks are isolated in the adapter and covered by native tests. Output is composited on white. PDF embeds this image on one page; it does not provide selectable text or pagination. Only local `blob:` fetches were added to CSP to allow attachment-image rendering; external network access remains restricted. The existing `pdf-lib` transitive version is now a pinned direct dependency.

`src-tauri/src/exports.rs` validates formats, safe archive paths, duplicate names and a 100 MiB aggregate payload cap. Output is written to a unique sibling temporary file, synced, then published with `tempfile::persist_noclobber` (a no-replace move on Windows). Failed writes clean up the temporary file and preserve existing destinations. Paths are supplied only by the native dialog. Visual exports are bounded to 16 megapixels and 16,000 pixels per side. Exports are currently in-memory IPC and are not intended for multi-gigabyte documents.

The integrity panel runs a read-only SQLite integrity/foreign-key check and the attachment hash/size audit after flushing pending editor saves. It lists affected attachment keys, filenames and stored document associations, including Trash, without rewriting snapshots. Associations are import history, not proof of current in-document use. Unindexed regular files directly in assets or one subfolder deep are listed and retained; a known hash at the wrong path is also unindexed. The report is timestamped, cleared before a new attempt and on workspace transitions, and links to backup management for separate-workspace recovery. Audit failures use the existing error/retry path. Large audits remain serialized and are not paginated; full schema validation and automatic repairs remain future work.

`quarantine.rs` adds explicit recoverable cleanup outside the attachment index. Preview scans ordinary files directly in `assets` and one level below, hashes their bytes and excludes any filename or content hash present anywhere in `attachments`. Thus indexed bytes remain protected even when associated only with Trash, no document, or a shared source. SQLite integrity and foreign-key checks must pass before preview/move. Unsupported relative names, links and Windows reparse points are excluded; no recursive traversal is performed. The broader integrity inventory can list files that this more conservative cleanup preview excludes.

Commands accept workspace-scoped candidate IDs plus preview size/hash, or quarantine UUIDs; the frontend cannot supply destination paths. The workspace mutex serializes preview revalidation and moves against Knot writes. Each selected file is matched against a fresh scan and rehashed before copying. A unique `quarantine/<UUID>/entry.json` records its relative original path, size, hash and time. Metadata and an independent no-replace payload copy are synced and verified before removing the source. Partial batches report per-file outcomes; interrupted or malformed entries remain on disk with catalog warnings. No database rows, document bodies, IDs, organization or attachment relationships are changed.

Restore validates the metadata and payload, validates ordinary parent directories, refuses existing destinations, and refuses content that conflicts with a newly indexed original path. It publishes a synced copy without replacing files and retains the quarantine payload even after successful restoration. Refresh and workspace transitions clear selections, and mutations flush pending editor saves. Recovery copies can still be listed if cleanup preview fails. Quarantine uses disk space and is intentionally excluded from existing backups and copy-based relocation, which already exclude unindexed files; the UI states this limitation. Permanent disposal is described below; general empty-directory cleanup, recovery-copy portability, pagination and cancellation are not implemented. Scans and payload verification are synchronous under the workspace mutex. External applications modifying workspace files concurrently and physical power-loss/full-disk behavior are not guaranteed by this slice.

The integrity command also captures catalog metadata and saved snapshot pairs for all live and trashed documents under the workspace mutex. The frontend decodes them into disposable Yjs documents, never into the active editor or a BlockSuite collection. It checks collection metadata identity, unresolved Yjs dependencies and exactly one page root, then checks card and inline target IDs against the complete catalog. Self references and cycles are valid; missing, trashed and unreadable targets receive distinct findings with source IDs. Missing snapshots are reported as possibly never opened, not proof of content loss. Snapshots are discarded after analysis; only findings remain in React state. No repair, migration or reference rewrite occurs. This is structural diagnosis, not full block-schema, attachment-use or rendering validation. All snapshot bytes currently cross IPC in one report and decoding runs synchronously in the WebView; large-library memory, pagination and cancellation remain future work. Existing read failures abort the report rather than showing stale success.

The report groups referenced Trash targets that pass the basic snapshot checks into explicit recovery actions, counting distinct referring documents including trashed sources. Missing or structurally damaged target snapshots do not receive a direct action; their findings point to document issues and recovery backups. Before acting, the shell flushes pending edits and reruns the audit, rejecting stale actions whose targets are no longer eligible. It reuses the existing restore command, which changes only the original object's deletion flag. The shared restore flow refreshes library/Trash, reconstructs the active editor collection without a history visit and reruns any visible integrity report. A committed restore is announced before subsequent refresh work, so a refresh failure cannot hide that it succeeded. Failed database restores leave the current report available for retry. No automatic batch restoration, snapshot replacement or migration is introduced; basic checks do not guarantee complete schema/rendering validity or healthy transitive dependencies. Revalidation is serialized with app actions but does not guarantee against external filesystem/database writers.

Database upgrades now pass through `migrations.rs`. Workspace manifest format 1 and SQLite schema 3 remain current; Yjs updates remain opaque bytes and are never rewritten by a database migration. Unsupported database versions are rejected before journal-mode changes. Version 0 initializes only when the database has no user schema, with all three migrations and the final version in one transaction. Schema 1 and 2 upgrades require SQLite integrity/foreign-key checks and consistent migration history, then create a unique `backups/pre-migration-schema-<version>-<UUID>.knot` archive inside the workspace. The exporter captures a coherent SQLite snapshot and manifest plus all indexed attachment hashes (including shared and Trash associations); migration additionally checks stored asset sizes, reads every ZIP entry through CRC verification, and enforces the existing restore limits before changing schema.

Schema changes, migration history and `user_version` commit together after post-migration database validation. SQL failures roll back and report the retained archive location. Retry creates a new archive without replacing prior recovery copies; opening an already-current database creates none. The integrity report lists the current database schema and retained archive paths with instructions to use the existing native Restore backup dialog. Archive listing does not revalidate contents. Restoration creates a separate workspace and upgrades that recovered copy through the same safeguards; it does not downgrade the active database. These archives are local recovery material, excluded from ordinary backup archives and copy-based relocation, and omit unindexed files/quarantine like other backups. They have no automatic retention, deletion UI or scheduling. Legacy opening/backup verification now needs additional space and attachment I/O; missing/corrupt indexed assets block migration. External database/filesystem writers, very large archives and physical disk-full/power-loss are not guaranteed by this slice.

Permanent orphan disposal operates only on an individually selected complete quarantine entry. Confirmation identifies the original name, recovery UUID and payload byte count and states that deletion cannot be undone. The shell flushes edits before invoking the command and refreshes the catalog after success or rejection. Under the workspace mutex, Rust compares all previewed metadata against the freshly verified entry, checks SQLite integrity/relationships, and refuses any payload hash or original filename present in the attachment index (including missing indexed assets, Trash and shared sources). Unexpected directory contents, redirects, damaged payloads and stale metadata are rejected. It revalidates the entry immediately before deleting only its payload, then removes its metadata and empty directory without recursive deletion. Restored originals, database rows and other entries are untouched. A metadata-cleanup failure after payload deletion returns a success warning; interrupted cleanup leaves remaining metadata visible as a catalog warning. This releases the selected payload's storage, not necessarily an equal change in filesystem free-space accounting. No bulk disposal, secure erasure, external-writer race guarantee or damaged-entry deletion is provided.

Missing-attachment recovery reuses the conservative ordinary-file/path checks in `quarantine.rs`. The integrity panel offers one action per missing hash, disabled for reported database issues. After flushing pending saves, the backend checks current SQLite integrity and relationships, requires the hash still be indexed with one consistent size, validates destination parents and refuses any occupied destination, including corrupt files, directories and links. It searches regular asset files directly in assets or one subfolder deep, then complete verified quarantine entries. Matching requires exact SHA-256 and indexed size; neither attachment keys nor associations are inferred or rewritten. The selected source is copied to a synced temporary file and that copy is verified before no-replace publication at the indexed path. Sources and recovery metadata remain intact. The shell announces committed recovery, reconstructs the active editor to refresh cached attachments/shared previews and reruns integrity diagnostics. Missing parent directories may be created even when no source is found. Scanning/hashing remains synchronous under the workspace mutex and may be expensive for large libraries; no recursive search, cancellation, external file selection, archive extraction, corrupt-file replacement or hostile filesystem-race guarantee is included. Quarantine catalog failures conservatively abort recovery before publication.

Milestone 4 backlinks are an on-demand, read-only projection of existing stable `pageId` references. The shell flushes pending edits and reads the live paginated catalog, then loads each other source snapshot sequentially through the existing repository API. Isolated Yjs documents validate collection identity, dependencies and page-root presence before extracting shared-card, link-card and inline targets. Each source appears once, ordered by title/ID; self links and Trash sources are excluded. Null snapshots (never-opened documents) have no saved backlinks. Invalid snapshots are listed as partial-result warnings, while storage/transport failures abort the scan and clear old results. No attachment audit, persistent index, body conversion or schema change is involved.

The panel states that results reflect the last scan and offers explicit refresh. Source navigation rechecks the live catalog and uses the existing flush/history path. Successful document selection, deletion and workspace reset clear the panel. App actions and editing remain locked during scans; only result metadata remains in React state. This is a whole-library scan with one snapshot pair in memory at a time, not an incremental index; large-library latency, cancellation and concurrent external database writers are not covered. Integrity checks remain the separate diagnostic path for unreadable documents.

PDF highlight cards use the pinned PDF.js 6.4.299 renderer and text layer in a lazy-loaded React reader. The reader lists PDF attachment blocks in the active document and reads their original keys through the existing hash-verifying BlobSource command. It renders one page at a time, captures a single-page text selection and normalized rectangles, and can reopen that page with the rectangles highlighted and scrolled into view. Workers, CMaps, standard fonts and WASM resources are bundled locally by Vite; no remote document/resource URLs are accepted. CSP now permits same-origin resource fetches and blob fonts. PDF viewer styles are scoped to the reader, and loading/render tasks are cancelled and disposed on transitions.

Cards remain native `affine:note` blocks with a quote paragraph and a source-link paragraph, visible in Page and Canvas and governed by BlockSuite undo/redo. A validated `https://knot.invalid/pdf#...` sentinel link carries the attachment key, originating document ID, filename, one-based page and normalized rectangles. The session intercepts these links, including popup/auxiliary clicks, to open the local reader; this is not a web service. The original PDF remains authoritative and unmodified. Links resolve by workspace attachment key even if the original attachment block is removed or its document is trashed, since indexed assets remain retained. These workspace-local source links are not portable PDF annotations in ordinary exports.

The shell flushes before opening the reader and creating a card. A per-selection block ID makes retry after a rejected save idempotent; pending card edits remain in the existing SaveCoordinator. Cards are placed beside existing notes to avoid overlap when an embedded PDF later expands its native note height. BlockSuite may update note layout during Page/Canvas rendering; original attachment blocks, bytes and associations are not rewritten. Document/workspace changes clear the reader. No custom block schema, second canvas engine, database migration or Yjs conversion is introduced.

Limits: 10 MiB per PDF, at most 4 megapixels/8,000 pixels high per rendered page, 4,000 selected characters and 100 normalized rectangles per card, and a 20,000-character source-link cap. The existing attachment IPC still reads the file before applying the reader size limit. Password-protected PDFs are refused; blank/image-only pages have no selectable text. Text extraction order and complex/rotated/font fidelity depend on PDF.js and are not guaranteed for every PDF. Cross-page selection, OCR, editing the PDF, persistent in-file annotation and a workspace-wide PDF catalog remain future work. Editing a quote or source link manually changes ordinary document content; it does not update the original PDF.

The unified PDF reader uses local PDF.js with page navigation, zoom, fit-to-width and highlight creation. All PDF entry points share its resizable panel; selection review appears when text is selected. Office preview and its XML worker have been removed; existing Office attachments remain ordinary attachments.

Advanced search is an explicit saved-content scan, separate from the sidebar's automatic title filter. Search/Refresh flushes edits, reads up to 200 live objects through the existing collection-filtered query, and reads one snapshot pair at a time. A disposable worker validates identity, complete Yjs updates and a single page root, then extracts native paragraph/heading, list and code `prop:text` values. Titles are always searched; attachment contents, tables, captions, surface text and transcluded bodies are excluded. Literal trimmed case-insensitive substring matching yields one stable-ID result with a 220-character excerpt, ordered by title/ID. Results carry scan time and require explicit refresh after edits; query/filter changes and document/workspace transitions clear them.

Search caps decoding at 1 MiB per snapshot pair, 16 MiB total, 100,000 extracted characters and five seconds per document. Individual corrupt/oversized/timed-out bodies produce partial-result warnings while retaining title matches; catalog truncation is explicit. Storage errors abort and discard stale results. Existing snapshot IPC reads a whole pair before frontend size checking, so this is a decoding bound, not a backend allocation limit. The worker is reused sequentially within one search and terminated on completion/failure. No persistent index, migration, write or active-collection hydration occurs. External-writer consistency, cancellation and large-library latency remain outside this slice.

## Notebook navigation

The library presents each existing document as a notebook, independent of its creation kind. Selecting a notebook exposes collapsible Whiteboard/Page navigation and a live list of its native note blocks. Note labels use their first nonempty text block, falling back to a numbered label. Choosing a note opens only that note in Page, including notes normally hidden from the full page. Other note bodies and the document-wide heading are omitted from this focused view; the shell keeps the notebook title for context. Selecting one note on Canvas and using the header Page switch does the same; the sidebar Page view resets to the full page. A per-editor BlockSuite 0.19.5 renderChildren bridge limits the page rendering filter to the selected note without changing its persisted displayMode. Select-all is limited to the focused note, and view transitions clear old selections. Switching views or reopening clears the reveal; edits use the original note body and normal save/undo paths. Shared-document placements are labeled Linked and open their source through the normal save/history path. The active notebook alone loads its contents, avoiding eager hydration of the whole library. Updates, deletions and undo refresh the list from the existing Yjs document. Storage IDs, bodies and ownership are unchanged.

## Mini browser

A Rust-owned native child webview occupies the supporting Browser tab without replacing the trusted app webview or weakening its CSP. The shell's external-link router handles actual editor/card Open actions; native URL validation, caller checks and webview-scoped capabilities isolate remote content from every application command and app asset. Browser history and page state come from WebView2. A dedicated temporary InPrivate profile is disposed only after successful workspace transitions or normal app close. See [Mini browser v1](MINI-BROWSER.md) for lifecycle, storage policy, limits and native verification.


## Supporting tabs and shared Page views (6 November 2026)

`App` separates management/transient `surface` state from the supporting layout saved per notebook and workspace. `workspace-layout.ts` contains metadata and pure transitions; `WorkspacePanes` projects zero, one or two supporting groups from the measured content-row width. All content panels stay in one flat keyed list. Split, merge and reorder change positions without reparenting live controllers. Inactive panels retain layout geometry but are inert and excluded from accessibility. `useNotebookLayout` stores versioned, validated tab identities, group membership/order, active tabs, last-used group and widths in local preferences under `knot.notebook-layout.v1` keys containing both workspace and notebook IDs. Empty layouts persist too. Notebook changes load preferences before rendering panes; malformed records fall back to a valid layout. Layout preferences contain no editor instances or document snapshots. Startup reopens the last available notebook from the workspace sidebar history, with the first-run tour taking priority.

A note pane calls `EditorSession.createNotePageView`, never `openEditor`. The same collection, active `Doc`, BlobSource, SaveCoordinator and undo history back Canvas and all supporting Page hosts. An instance-local Page-root `renderChildren` bridge filters the note without touching stored display modes. View disposal removes only its subscriptions, presentation observers and DOM. Session disposal first releases attached views, then the collection. Document navigation retains the established awaited save boundary, disposes the previous notebook's views and restores the destination notebook's own tabs. PDF sources are reloaded from the current session. Browser/Card Deck retain their existing content semantics while their tab placement is notebook-specific; Ask is rebound at document boundaries.

Native browser placement remains serialized and physical-pixel based. A revision drops stale queued placements; hidden/inert tabs, management overlays and a document-level pane-gesture flag suppress the single native child. Moving the Browser tab never recreates or navigates its session. PDF citation navigation updates the mounted reader's location rather than changing its React key.


## Explicit website evidence

Ask Knot's source coordinator owns request-generation cancellation and immutable captures, independently of the native mini browser. Trusted-shell commands in `web_sources.rs` fetch public HTML/text with manually revalidated redirects, public-IP validation and pinned DNS answers, no proxy/cookies/AI headers, normal TLS verification, bounded streaming/decompression and deadlines. No workspace lock is held during networking. Readability plus LinkeDOM's worker entry extracts inert structured plain text in a terminable Vite worker. The shared context composer selects bounded passages with per-source coverage manifests; saved native web-source children can feed the same composer when improving cards.

The model receives a frozen capture/section reference table. Web-enabled edit schemas require per-content/connector/node sourceRefs, resolved against that exact table before editor mutation. `knot:web-source` is a native content child, with schema/service/view registration and export/clipboard adapters. It participates in content signatures, shared Card Deck content, grouped native Undo, snapshots, search and normal backups. Pure sourced mind maps gain a companion source card; mixed maps retain node evidence in an accompanying generated card. Browser capture and remote PDFs remain follow-ons. See [AI behavior](AI.md) and [verification](AI-WEB-SOURCES-VERIFICATION.md).
